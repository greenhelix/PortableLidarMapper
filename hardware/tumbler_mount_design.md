# 텀블러 마운트 설계도 (초안)

> RPLIDAR C1 실측 후 치수를 채워넣는 작업 문서. 지금은 뼈대만 잡아둔다.

## 0. 장비 장착 현황 (2026-09-10 기준)

| 부품 | 상태 |
|---|---|
| RPLIDAR C1 | ✅ 보유 (PC로 실측/실사용 검증 완료) |
| Orange Pi 4 Pro 4GB | ❌ 미구매 (`hardware/board_price_tracking.md` 참고) |
| 텀블러/보온병 케이스 | ❌ 미확정 (후보 실측 전) |
| 보조배터리 | ❌ 미확정 (5V/3A 이상 출력 필요, 아래 1번 참고) |
| 평탄화 디스크/브라켓(3D프린팅) | ❌ 설계 전 |
| IMU(관성 측정 장치) | ❌ 미구매, Phase 2 향후 항목 (1.5번 참고) |

즉 지금은 **소프트웨어(Docker 이미지)만 준비된 상태**이고, 물리적 조립은 전부
착수 전이다. 아래 내용은 구매/제작 전에 미리 정리해두는 사양·리스크 문서다.

## 1. 전원/파워 규격

- **Orange Pi 4 Pro**: USB-C, **5V/3A(15W)** 입력. 일반 고속충전 보조배터리로
  충분할 가능성이 높음 (Raspberry Pi 5의 5V/5A 요구보다 낮음). 상세 비교는
  `hardware/board_price_tracking.md` 참고.
- **RPLIDAR C1**: 별도 전원 없이 **USB 버스 파워**로 동작 (모터+레이저 포함).
  보드의 USB 포트에서 직접 공급됨 — 즉 보드에 안정적으로 전원이 들어오면
  라이다는 자동으로 같이 해결됨. 다만 보드의 USB 포트 자체가 라이다 기동
  순간(모터 스핀업) 전류 스파이크를 감당할 수 있는지는 **실측 전 미지수**
  (`hardware/orange_pi_4_pro_bringup_risks.md` 3번 항목).
- **배선 우선순위**: 보조배터리 → (USB-C) → Orange Pi 4 Pro → (USB-A, 내부 케이블) → RPLIDAR C1.
  즉 배터리는 보드 하나에만 연결하고, 라이다는 보드를 거쳐 전원을 받는 구조 —
  배터리를 라이다에 직접 연결할 필요 없음(라이다는 표준 USB 전원 규격 5V를 씀).
- **필요한 배터리 용량(추정)**: Orange Pi 4 Pro(15W) + RPLIDAR C1(공식 스펙상 약 2~3W)을
  합쳐도 20W 미만. 10,000mAh(약 37Wh)급 보조배터리면 이론상 1.5~2시간 이상
  구동 가능할 것으로 추정(발열로 인한 스로틀링/변환 손실 감안 시 실측 필요).
- **확인할 것(구매 전 체크리스트)**:
  - [ ] 보조배터리 출력이 5V/3A(15W) 이상 명시돼 있는가
  - [ ] USB-C 케이블이 3A 이상 대응인가 (저가 케이블은 못 버티는 경우 있음)
  - [ ] 보조배터리의 "자동 절전(저전류 자동 꺼짐)" 기능이 있는지 — 있다면 SBC의
    안정적인 지속 전류 소모와 충돌해서 꺼질 위험은 낮지만, 혹시 모르니 구매
    후 장시간(30분+) 구동 테스트 필요

## 1.5 IMU(관성 측정 장치) 확장 계획 (2026-09-10, 향후 Phase 2)
IMU(Inertial Measurement Unit, 관성 측정 장치 — 자이로스코프+가속도계가 들어있는
저가 센서 모듈, 회사 이름 아님)를 나중에 추가하면 회전/기울기 추정 정확도가
올라간다 (devlog 참고). 아직 구매 전이지만 마운트 설계에 미리 자리를 반영해둔다.

- **원칙: IMU는 라이다와 같은 강체(rigid)에, 최대한 가까이 고정한다.** IMU가
  측정하는 건 "IMU 자신의" 기울기라서, 구조물이 조금이라도 휘면 라이다의 실제
  기울기와 오차가 생긴다.
- **위치**: 상단 평탄화 디스크(라이다 바로 아래)에 같이 부착 — 별도 브라켓 불필요,
  디스크 설계에 IMU 고정 홈만 추가.
- **배선**: I2C 통신(선 4개: 전원/접지/데이터 2선)이라 부피가 작음. 기존 라이다
  USB 케이블이 내려가는 관통홀을 같이 씀 — 별도 홀 안 뚫어도 됨.
- **가격/부착 가능 여부**: 저가형(MPU6050급) 기준 3,000~7,000원, Orange Pi 4 Pro의
  GPIO I2C로 연결 가능 (정확한 핀 번호는 보드 실물 핀아웃 문서로 확정 예정).
- **소프트웨어**: `base_footprint→imu_link` 고정 좌표(TF) 등록 + `robot_localization`
  (EKF)으로 rf2o와 융합. 지금 당장은 안 함 — Phase 2, 몸통 가림 등 더 급한
  물리적 문제 해결 이후로 순서를 미뤄둠.

## 1.7 부품 치수 기반 부착 가능성 검토 (2026-09-10)

라이다(⌀75mm×H40mm)/Orange Pi 4 Pro(89×56mm, 웹 검색으로 실치수 확인)/IMU(21×16mm)
크기를 실제로 겹쳐서 스케일 다이어그램으로 검토함.

- **결론: 완전 커스텀 하드케이스는 불필요.** 지름 제약의 진짜 병목은 라이다
  (⌀75mm)지 보드나 IMU가 아님 — 보드를 세로로 세우면(89mm를 높이 방향, 56mm를
  지름 방향으로) ⌀70~90mm대 텀블러에 여유 있게 들어감.
- **다만 "그냥 부착"도 아님** — 사각형 보드가 원통 안에서 저절로 안 서 있으니,
  세로로 고정해줄 작은 내부 브라켓("슬레드")은 필요. 이미 4번 파츠 목록에 있던
  "보드 고정 브라켓"과 동일 항목 — 새 작업 추가가 아니라 필요성이 치수로 재확인됨.
- **남은 진짜 불확실성**: 텀블러 후보 3종을 아직 실측 안 함. 실제 안지름(내경)이
  56mm보다 좁은 극단적 모델이면 이 결론이 바뀔 수 있음 — 그래서 7번 TODO의
  "텀블러 실측"이 지금 제일 중요한 다음 행동.

## 2. 기준 치수 (RPLIDAR C1 공식 스펙 기준, 실측 전)
- 라이다 본체 지름: 약 75mm
- 라이다 높이: 약 40mm (하단 케이블 커넥터 제외)
- 스캔 평면: 라이다 상단면 기준 수평, 360도

## 3. 조립 순서 (개념)
1. 텀블러/보온병 뚜껑을 제거하고 평탄화 디스크로 대체
2. 평탄화 디스크 중앙에 C1 장착 구멍(지름 75mm) 가공 또는 3D프린팅
3. 디스크 하단에서 USB 케이블을 텀블러 내부로 관통
4. 텀블러 내부 중~하단에 보드(Orange Pi 4 Pro) 고정 브라켓 배치
5. 최하단에 보조배터리 배치 (무게중심 하향)

## 5. 검증 체크리스트 (프로토타입 완성 후)
- [ ] 텀블러를 기울여도 라이다 스캔 평면이 수평을 유지하는가
- [ ] 걷는 진동에서 SLAM 지도가 심하게 왜곡되지 않는가
- [ ] 보드 발열이 케이스 내부에 갇히지 않는가 — Orange Pi 4 Pro는 부하 시 90°C까지
  금방 올라간다는 실제 리뷰가 있어(`hardware/orange_pi_4_pro_bringup_risks.md`),
  패시브 방열판만으론 부족할 가능성 높음. **통풍 구멍 + 액티브 쿨링팬을 기본
  전제로 설계**
- [ ] 배낭 측면 포켓에 들어가는 전체 높이/지름인가

## 6. 백팩 측면 포켓 장착 시 예상 문제 & 데이터 수집 전략 (2026-09-10)

실제 착용 형태(백팩 옆 물병 주머니에 텀블러를 꽂고 다니는 방식)를 미리 따져보면,
지금까지 PC 테스트에서는 없던 문제가 새로 생긴다.

### 문제 1: 몸통에 의한 만성적 반쪽 가림 (자기 그림자)
라이다가 몸 옆(측면 포켓)에 있으면, **몸통을 향한 방향은 항상 몸/가방 본체에
가려진다.** PC에서 손에 들고 테스트할 때 겪었던 "몸이 순간적으로 가리는" 문제
(devlog 2026-09 기록)와 달리, 이건 **일시적이 아니라 상시 발생하는 가림**이라
훨씬 심각하다. 360도 중 실질적으로 유효한 시야는 몸 바깥쪽 절반 정도로 예상.

- **대응 방향 (구현은 나중, 지금은 설계 메모)**:
  - 몸쪽으로 향하는 특정 각도 범위는 처음부터 "믿을 수 없는 데이터"로 간주하고
    필터링(각도 마스킹)하는 게, 그 잘못된 근접 반사를 지도에 벽으로 잘못 새기는
    것보다 낫다 — sllidar 드라이버 또는 그 이후 전처리 노드에서 특정
    `angle_min`~`angle_max` 구간을 무시하는 옵션 검토.
  - 한쪽이 항상 안 보이는 게 원천적 한계이므로, **제자리에서 도는 게 아니라
    실제로 몸 방향을 바꿔가며(또는 건물을 한 바퀴 도는 경로로) 이동해야
    사각지대가 채워진다** — 이전에 "회전만으론 안 되고 이동해야 한다"고
    정리했던 결론이 여기서는 "이동뿐 아니라 몸의 방향 자체도 바꿔야 한다"로
    한 단계 더 강해짐.

### 문제 2: 걸음걸이로 인한 주기적 다리 가림
측면 포켓 높이는 대략 골반~허벅지 높이. 이 높이는 **걸을 때 자기 다리가 스캔
평면을 주기적으로 스쳐 지나가는 높이**다. 문제 1(상시 가림)과 별개로, 걸음
주기마다 반복적으로 짧은 거리(다리)가 잡혔다 빠졌다 하면서 노이즈를 만들 수 있다.

- **대응 방향**: 최소 감지 거리(`range_min`) 조정이나, 아주 가까운(수십cm 이내)
  반사는 신뢰도를 낮게 주는 후처리를 고려. 근본적으로는 마운트 높이를 허벅지보다
  높게(허리~가슴 높이) 가져가는 게 이상적이지만, 그러면 무게중심이 올라가서
  안정성과 트레이드오프 — 실측 프로토타입에서 직접 비교 필요.

### 문제 3: 흔들림/기울기 안정성
포켓은 물병 정도 굵기를 헐겁게 잡아주는 구조라, 걸을 때 완전히 고정되지 않고
흔들리거나 살짝 기운다. 2D 라이다는 기울기에 취약하다는 게 이미 확인된 근본
한계(devlog 2026-09-04) — 여기에 포켓의 헐거운 고정력까지 더해지면 실제로는
PC 손잡이 테스트보다 더 불안정할 수 있다.
- **대응 방향**: 텀블러 하단부를 포켓 폭에 맞춰 약간 타이트하게(또는 포켓 안에
  고정 스트랩 추가) 만드는 물리적 보완이 소프트웨어 튜닝보다 우선.

### 문제 4: 상단 돌출부 충돌/노출
라이다가 케이스 상단에 있어야(가려지지 않게) 하니, 가방 위로 튀어나오는 구조가
된다 — 문틀, 나뭇가지, 사람 어깨 등에 부딪힐 위험. 실사용 전 라이다 상단에
간단한 충격 보호 캡(스캔은 방해 안 하는 낮은 테두리 정도) 검토.

### 데이터 수집 전략 요약
1. 몸쪽 사각지대는 소프트웨어로 마스킹하거나 무시 (완전히 없앨 수 없는 한계로 인정)
2. 같은 자리에서 뱅뱅 돌기보다 **실제로 공간을 걸어서 순회**하는 방식으로 수집
   (여러 지점에서 "바깥쪽 절반"이 겹치면서 전체 커버리지 확보)
3. 마운트 높이는 허리~가슴 사이에서 실측 프로토타입으로 절충점 탐색
4. 정지 테스트(Phase 1, PC)에서 이미 튜닝한 노이즈 필터링(occupancy 확정 기준)이
   이런 실사용 노이즈에도 여전히 도움이 되지만, 완전한 해법은 아님 — 최종적으로는
   실제 착용 후 현장 검증(Phase 2)에서 재조정 필요

## 7. 확장 아이디어: 소형 카메라 (Phase 1·2 완료 후 검토, 2026-09-10)
저화질 소형 카메라를 추가해서 사물 인식(방/가구 라벨링)에 쓰는 아이디어를 검토함.

- **정확도/속도 향상용으로는 부적합**: 몸통 가림 문제를 못 풀어주고(카메라도 같은
  방향에서 같이 가려짐), 빠른 회전 시 저가 카메라는 모션 블러로 오히려 라이다보다
  약함. 이 두 문제의 정답은 카메라가 아니라 IMU(1.5번).
- **가치가 있는 지점은 "의미 부여"**: "이 방은 침대가 있으니 침실" 같은 라벨링은
  `ai/` provider + `lidar_mapper_db`(방/가구 메타데이터) 구조와 맞음 — 지도의
  정확도가 아니라 풍부함을 더하는 별도 기능.
- **주의**: Orange Pi 4 Pro가 이미 발열로 스로틀링되는 걸로 확인된 상태(위험 문서
  참고)라, 카메라+인식 모델 연산을 더 얹으면 오히려 전체 성능이 나빠질 수 있음.
- **순서**: Phase 1(지도 품질)과 Phase 2 초반(몸통 가림 등 물리적 문제) 해결
  이후에나 검토할 항목. 지금 할 일 아님 — 아이디어만 기록.
