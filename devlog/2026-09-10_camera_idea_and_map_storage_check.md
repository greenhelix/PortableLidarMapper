# 2026-09-10 개발 로그 (2) — 카메라 확장 아이디어, 지도 저장공간 오해 해소

## 오늘의 목표
- 텀블러 마운트 치수 검토(부품 실치수 기반) 문서화
- 카메라 확장 아이디어 로드맵 기록
- "지도가 넓어지면 저장공간을 많이 쓰는가" 확인

## 진행 내용
- **부품 치수 검토**: RPLIDAR C1(⌀75mm×H40mm), Orange Pi 4 Pro(89×56mm, 웹
  검색으로 실치수 확인), IMU(21×16mm)를 스케일 다이어그램으로 겹쳐봄. 결론:
  완전 커스텀 하드케이스는 불필요, 보드를 세로로 세우면 대부분의 후보 텀블러에
  들어감 — 다만 세로 고정용 작은 내부 브라켓은 필요(이미 계획에 있던 항목,
  치수로 재확인). `hardware/tumbler_mount_design.md` 1.7번에 반영.
- **카메라 확장 아이디어**: 프로젝트와 별개로 "STB에 라이다를 붙이면 어떨까"
  브레인스토밍을 하다가, 저가 카메라를 이 프로젝트에 붙이는 것도 같이 검토.
  결론: 몸통 가림/빠른 회전 문제는 카메라로 안 풀림(오히려 저가 카메라는 모션
  블러로 더 약함) — 이 두 문제엔 IMU가 정답. 카메라는 "사물 인식으로 지도를
  풍부하게" 라는 별도 가치가 있고, Phase 1·2 완료 후에나 검토할 항목으로 기록.
  `hardware/tumbler_mount_design.md` 7번에 반영.
- **저장공간 오해 해소**: 사용자가 "지도가 넓게 잡히는데 저장공간 많이 쓰는거
  아니냐"고 질문 — 확인 결과 **`/map`은 RAM에만 있고 디스크에 저장 안 됨**,
  저장공간 문제 없음. 다만 확인 과정에서 **이 컨테이너가 또 2일간 방치되어
  있었던 걸 발견**(이번엔 사용자가 아니라 내가 직접 만든 실수 — 수동 테스트
  명령에 로그 순환 옵션을 빠뜨림, 실제 로그 16.6MB 무제한 누적 중이었음).
  컨테이너 중지로 정리함.
- **리셋 기능 조사**: `/slam_toolbox/clear_changes`(타입 `slam_toolbox/srv/Clear`)
  서비스 존재 확인했으나, 실제 호출 시 응답 없이 걸려서 정확한 동작(전체 지도
  초기화인지, 수동 보정 취소용인지)은 검증 못 함 — 지금 확실한 리셋 방법은
  컨테이너 재시작뿐. Flutter 앱의 "세션 상태/리셋 패널" 아이디어로 로드맵에 기록.

## 막힌 문제 & 해결
| 증상 | 원인 | 해결 방법 |
|---|---|---|
| 컨테이너가 또 2일 방치됨 | 이번엔 Claude 본인이 RViz2 수동 테스트 시 `--log-opt` 로그 순환 플래그를 빠뜨림(run_dev.sh 스크립트를 안 쓰고 직접 docker run 명령을 짜서 발생) | 컨테이너 중지. 앞으로 수동 docker run 시에도 항상 로그 순환 플래그 포함하도록 스스로 체크 |
| `clear_changes` 서비스 호출이 응답 없이 걸림 | 정확한 원인 미확인(인터랙티브 모드 전제 조건일 가능성, 또는 exec 세션의 DDS 디스커버리 지연) | 미해결 — 지금은 컨테이너 재시작으로 우회, 필요시 추후 재조사 |
